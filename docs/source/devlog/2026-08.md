# Development log - 2026-08

## 2026-08-31 - Review findings gained explicit actionability

**Result**

- Every reviewer finding now classifies actionability independently from
  severity, while report-only findings remain visible without entering native
  repair threads.

**Why / context**

- Severity alone cannot say whether the current change owner must act. The
  separate field keeps provider reports complete while making convergence and
  merge gates deterministic.

**Evidence**

- PR #84 refreshed Codex, Claude, and Hermes contracts and added a low-severity,
  non-actionable fixture that stays out of the recording publisher.

**Links**

- [Pull request #84](https://github.com/sympoies/agent-runtime-kit/pull/84)
- [Code review catalog](../../../core/skills/code-review/README.md)

## 2026-08-28 - Review discovery and repair were bounded

**Result**

- Review convergence now permits one broad discovery generation and restricts
  repair review to the admitted finding set.

**Why / context**

- Unbounded rediscovery can turn delivery into an endless moving target. The
  closed-set repair phase preserves defect coverage while making completion
  and escalation conditions explicit.

**Evidence**

- PR #72 aligned reviewers, delivery owners, provider activity, tests, and
  rendered surfaces on the same finding-admission contract.

**Links**

- [Pull request #72](https://github.com/sympoies/agent-runtime-kit/pull/72)

## 2026-08-26 - Long-running work adopted safe mailbox checkpoints

**Result**

- Managed long-running work must check authenticated coordination at safe
  phase boundaries and at least every five minutes, without interrupting an
  in-flight atomic operation.

**Why / context**

- Peer requests and overlap information need bounded attention, but mailbox
  state remains non-authorizing and cannot justify cancelling or widening the
  current operation.

**Evidence**

- PR #55 rendered the rule across supported products and covered the safe
  checkpoint and no-interruption boundaries.

**Links**

- [Pull request #55](https://github.com/sympoies/agent-runtime-kit/pull/55)
- [Session coordination policy](../../../core/policies/session-coordination.md)

## 2026-08-26 - macOS automation became deterministic-first

**Result**

- The macOS desktop workflow now selects the cheapest deterministic surface
  that can prove an outcome, gates on accessibility health, and uses tracked
  flow fixtures before unattended-safe claims.

**Why / context**

- GUI driving is useful but expensive and fragile. A capability ladder keeps
  approval boundaries intact while preferring stable APIs, accessibility, and
  repeatable flows.

**Evidence**

- PR #50 added the routing ladder, negative accessibility classes, reciprocal
  browser-test handoff, repeated-run threshold, and backend freshness audit.

**Links**

- [Pull request #50](https://github.com/sympoies/agent-runtime-kit/pull/50)

## 2026-08-11 - Startup memory reached cross-product parity

**Result**

- Codex and Claude now share one bounded, redacted, once-per-session startup
  memory contract at the stateless SessionStart boundary.

**Why / context**

- A shared lifecycle prevents product-specific recall drift while keeping
  memory advisory, size-limited, and retry-safe when delivery is blocked.

**Evidence**

- PR #37 covered both providers, the inclusive 768-byte boundary, retry
  behavior, packaging, policy, and retirement regressions.

**Links**

- [Pull request #37](https://github.com/sympoies/agent-runtime-kit/pull/37)

  and rendered goldens were moved to the canonical Sympoies repository.

**Why / context**
