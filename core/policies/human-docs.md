# Write for the reader

Start with the answer, result, or next action. Give the context needed to use it.
Keep one idea in each paragraph. Prefer two to four short sentences.

Use headings that tell readers what they can find or do.
Use a list for steps or parallel choices, and a table for comparisons.
Explain a new idea with one concrete example before adding detail.

Choose plain words and active verbs. Name who acts and what changes.
State uncertainty where it affects the decision. Keep evidence and limitations.

Avoid these patterns:

- Walls of bullets that each start with a bold label.
- Chains of em dashes and nested asides.
- A hedge in every sentence, such as “may potentially” or “generally speaking.”
- Filler openings and repeated summaries, such as “It is worth noting” or
  “In conclusion.”
- Entire paragraphs written on one long source line.
- Emoji headings, decorative emphasis, and jargon such as “delve” or “leverage.”

Wrap prose source lines at 120 characters or less. Use an earlier break for
wide text. Keep headings within 80 characters. Source wrapping does not shorten
a rendered paragraph: split the paragraph when its idea changes.

Keep commands, code blocks, and tables intact. Put long URLs in reference
link definitions. Preserve quoted text and historical records.

Before publishing, read the page as someone doing the task.
Can they find the answer, follow the example, and tell what to do next?
Passing lint supports this review; it does not replace it.
