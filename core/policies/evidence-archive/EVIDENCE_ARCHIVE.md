# Evidence Archive

The evidence archive makes skill-usage evidence durable and queryable beyond
the local agent-out runtime tree. It retains machine-emitted `skill-usage`
records; ordinary owner issues and the public-safe development log retain any
human-readable chronology that must survive the session.

## Lifecycle

Evidence moves through six stages. Each stage is owned by one surface; this
policy is the map, not a re-implementation of any of them.

1. **Produce** — parent outcomes emit `skill-usage.record.v1` envelopes into the
   agent-out runtime tree (`${AGENT_HOME}/out/projects/<owner__repo>/...`)
   during a session. Records are written **unconditionally** — regardless of
   whether an archive is configured — so they are a useful breadcrumb even on a
   machine that never archives. Each record carries a
   `producer { tool, nils_cli_version }` block so an archived record is
   attributable to the surface and CLI version that wrote it.
2. **Surface** — when the outermost workflow has a durable retention duty, its
   evidence-control-plane closeout reviews the exact candidate records and
   flags non-pass outcomes for owner routing. This is awareness, not durability:
   the runtime tree is scratch space that is **not** auto-reaped — records
   persist there until manually cleaned (`agent-out`) or migrated.
3. **Migrate** — the direct `evidence migrate` CLI copies
   records out of the runtime tree into the archive repository. Dry-run is the
   default; `--apply` writes, commits, and pushes. Migration is the durability
   boundary: once a record is archived and pushed, it survives any later cleanup
   of the runtime tree. The outermost workflow runs the dry-run and applies only
   the reviewed, approved candidate set. Unexpected blocks, scrub volume,
   unrecognized hosts, or dry-run errors stop the apply. The parent never
   re-implements migration; it only invokes the CLI. Manual `evidence migrate`
   remains available for event-driven drains.
4. **Store** — the archive repository holds the rollups, their `metadata.yaml`,
   scrubbed linked evidence, scrub logs, and a derived `catalog.json` (see
   Layout).
5. **Prune source** — the direct `evidence prune-source --archived-only` CLI
   removes local agent-out source run directories
   only after their raw `skill-usage.record.json` digest already exists in the
   archive `catalog.json`. Dry-run is the default; direct use requires explicit
   confirmation before `--apply`. The outermost workflow may drive this after
   verified migration, but applies only the reviewed, approved source set. The
   archive remains read-only for this command.
6. **Query** — `evidence discover` / `query` / `search` / `catalog` read the
   archive. These are read-only and are driven directly from the CLI.

## Archive repository

The archive is a standalone git repository, resolved (in order) from:

1. `--archive <path>` (explicit),
2. `$AGENT_EVIDENCE_ARCHIVE_HOME`,
3. the machine-local config `$XDG_CONFIG_HOME/agent-evidence-archive/config.yaml`,
4. the XDG data-home default
   `${XDG_DATA_HOME:-$HOME/.local/share}/agent-evidence-archive`.

No surface hardcodes the clone path. The archive is private; it is never
checked into a working repository.

### Layout

```
agent-evidence-archive/
  config/hosts.yaml      # authoritative host classification (schema: agent-evidence-archive.hosts.v1)
  evidence/<host>/<org>/<repo>/...   # archived skill-usage.rollup.v1 + metadata.yaml + scrub log
  catalog.json           # derived index (evidence.catalog.v1); regenerated by migrate --apply / catalog --write
  README.md
```

`config/hosts.yaml` is the authoritative classification of every provider host
whose evidence is archived. Each host declares a `class`:

- `personal` — retained at the maintainer's discretion.
- `employer` — retained only during an active employment relationship with the
  named employer; subject to whole-archive destruction on termination
  (`delete-on-termination`). Add an `employer` host only when a real
  employer-operated host is being archived; no placeholder entries.

A record can only be archived to a host present in `hosts.yaml`. This mirrors
the agent-plan-archive hosts model.

## Identity and host classification

The agent-out `<owner__repo>` directory slug carries no host. `evidence migrate`
resolves the host so a record lands under the correct `evidence/<host>/...`
path:

- It derives identity from the working repo's `cwd` → `origin` remote when the
  record's source can still be located, rejecting repointed or ambiguous cwd
  evidence instead of guessing.
- It applies one uniform `<owner__repo>` slug match rule for direct and nested
  source directories, so rescued old-cwd records cannot collide across repos.
- Under a single-host `hosts.yaml`, the sole host is used.
- Under a **multi-host** `hosts.yaml`, a slug-only record is ambiguous. Migrate
  refuses to guess: the record is reported as `blocked` and skipped. The
  operator re-runs with `--host <fqdn>` (a host present in `hosts.yaml`) to
  vouch for the records they recognize. This is a deliberate human decision, not
  an inference.

Blocked records are never fatal. A migrate run continues past every
unresolvable or unreadable record, reports them in `blocked`, and migrates the
rest. An all-blocked run is a successful no-op.

## Redaction discipline

Migration scrubs secrets **before** anything is written to the archive — raw
record bytes never reach the archive. Scrubbing uses the shared `nils-scrub`
pattern set (`REDACTED` token), runs over the rollup, metadata, and any UTF-8
linked-evidence children (binary children are copied verbatim), and writes a
scrub log alongside each record so a reviewer can see what was redacted. The
`evidence migrate` surfaces the per-record scrub summary
(`patterns_triggered` + `total_matches`) in the dry-run for review. Scrubbing is
never disabled. A working directory outside `$HOME` is itself redacted to
`[REDACTED]` rather than archived as an absolute path.

## Idempotency, copy-only migration, and source cleanup

Migration is **copy-only**: the agent-out source tree is left intact (migrate
never deletes from it). Records dedup by content digest, so re-running migrate is
safe — already-archived records are reported in `already_archived` and skipped.
There is no source-deletion step in migration and no working-repo push to
perform; the CLI commits and pushes only the archive.

Source cleanup is deliberately separate. `evidence prune-source --archived-only`
reads the archive catalog's `source_digest` values, computes each local source
record digest, and prunes only matching local run directories. Unarchived,
unreadable, or non-record directories are retained and reported. This keeps the
durability boundary unambiguous: migration proves archive retention first;
pruning later bounds local runtime state without deleting archive evidence.

## When to migrate

The trigger is event-driven and owned by
`core/policies/evidence-control-plane.md#closeout-and-retention`. When evidence
must survive the session, the outermost workflow reviews exact candidates,
runs `evidence migrate` dry-run-first, applies only the approved set, verifies
the archive, then may run `evidence prune-source --archived-only` through the
same review-before-apply sequence.

The runtime tree is not auto-reaped, so timing is not load-bearing: nothing is
lost by migrating or pruning later. Migration and pruning are not automatic
session-end or per-task steps. Whether driven by an owning workflow or run
manually, always review the dry-run before `--apply`; for pruning, always keep
`--archived-only`.
